# 记忆召回重建设计（MEMORY_RECALL_REBUILD）

> **状态：待拍板（2026-11-03 凌晨定方向，我醒后逐条确认）。**
>
> 本文档记录一次重大设计转向：**心事（pending）的生产与消费方式全部重做，
> 向量（embedding）从「只回填不召回」升格为核心召回链路。**
>
> 我的原话（语音转写，关键段）：
> 「心事的生产机制要改，不能一条摘要一个心事……
> 用重要性打分挑……每一次回复的时候用向量去找，根据上下文生成回复的时候，
> 每一次回复调用向量去找相关的记忆摘要，放入上下文……加提示词让他考虑要不要用。」
>
> 本文档只记**设计定稿方向**，代码实现等我确认后再排期。唯一真相源是
> `docs/ARCHITECTURE_MAP.html`，本文档是它的展开。

---

## 0. 一句话现状（2026-11-03 凌晨摸底）

**v3 的记忆系统「三套机制做一件事」，且心事生产与向量召回都没生效。**

- `summary`（长期记忆）、`fragment`（碎片）、`pending`（心事）三个 `kind`
  都挂在同一张 `memory_summaries` 表，源头都来自「群消息切批」；
- 心事靠 `/v1/summary` 顺带产出：**每条摘要吐一条 pending**，产生量 >> 消耗量；
- 心事 48h TTL，只有 proactive 私聊开口才消，堆积严重；
- 向量（embedding）阶段 3 只做了「回填」，**阶段 4 语义召回从未做**，
  向量白算，relevance（相关性）维度一直缺失；
- 轨B2 老 summary 兜底把「importance 打分决定是否记」删成了「skip 或摘要」。

---

## 1. 病根：三套机制做一件事

我诊断（原文）：「我为了一种效果，搞了三套东西。」

| 机制 | 表/kind | 原设计 | 实际问题 |
|---|---|---|---|
| summary 摘要 | kind=summary | 长期记忆，衰减沉底 | 正常 |
| fragment 碎片 | kind=fragment | 临时关注，3天TTL，升级即消 | 正常 |
| pending 心事 | kind=pending | 想主动说的话，48hTTL，开口即销 | **生产机制错 + 消太慢** |

三者不**完全**重复，但高度重叠——都回答「她看到群里的东西后怎么记、怎么联动」。

**真正的病根是 pending 的生产机制**：

```
/v1/summary 每次总结一段对话，顺带让 LLM 输出 pending 数组（"她心里挂着的一句话"）
        ↓
每条 summary → 1 条 pending → write_pending 落库
        ↓
摘要多 → 心事就多；消耗只有 proactive 私聊开口，产生量 >> 消耗量
```

**pending 不是独立的冲动信号，是 summary 的附庸。** 这是「心事太多、消太慢」的根。

## 2. 设计转向（我凌晨定方向）

### 2.1 心事生产：与摘要脱钩，独立判断「想说没说」（2026-11-03 清醒后定稿）

- **不再**「每条摘要吐一条 pending」；
- **不再**用 importance 打分切「≥9 分当心事」——因为「重要 ≠ 想说」：
  有些事重要但没话可说，有些事不重要却憋着想分享；
- **摘要**：回到原来的 `skip` 或「做摘要」粗判，**不打 importance 分**；
- **心事**：做摘要的**同一次调用**里，独立问一句
  「这段里有没有她想了但没来得及说的事？」，有才产出一条 pending；
- 心事独立占 `kind='pending'`，带 `outlet`（出口意向：private / qzone / both），
  **说出口的那一条才销账**（不是召回就销、不是全销）；
- 群聊里「想说没说」的也会被私聊带出——靠 48h TTL + 向量相关性匹配兜底，
  不会乱塞，保留。

### 2.2 心事消费：三个出口 + proactive 兜底

- **主出口一（私聊回复）**：每次回复时，按当前上下文向量召回相关心事/记忆，
  放进上下文 + 提示词「接话用摘要 / 抛话题用心事，要不要用自己判断」，不硬塞；
- **主出口二（空间发文）**：qzone 驱动捡 `outlet ∈ (qzone, both)` 的心事，
  公开审查后发；
- **兜底出口三（proactive 主动私聊）**：见 §2.4。
- 这是 RAG（检索增强生成）标准做法。

### 2.3 召回分：相关性（向量）+ 时间（半衰期）

```
召回分 = 相关性（embedding 余弦相似度） + 时间（半衰期衰减）
```

- relevance（相关性）维度**回来了**——之前抄 Generative Agents 时把相关性砍掉，
  一直缺；
- importance **不参与**召回排序（摘要不打分，心事也不打分）。

### 2.4 proactive 主动开口（触发与召回分离，2026-11-03 定稿）

**触发 ≠ 召回，两回事**：

| 概念 | 内容 |
|---|---|
| 触发 | 什么时候该主动来找我（心事积压到阈值） |
| 召回 | 触发后从心事里挑哪条说 |

**触发（积压驱动，非轮询掷骰）**：

```
心事（pending，该卡 48h 内活着、未销账）攒到 ≥ 5 条 → 触发主动开口
（5 是初值，上线跑一周后用真实产生频率回校）
```

**三层保险（防刷屏，我拍板）**：

| 层 | 内容 |
|---|---|
| ① 间隔层 | 两次主动开口最少隔 **3~4 小时**，且**加随机浮动**（不整点触发，防机械感） |
| ② 总量层 | **每天最多主动开口 3 次**（硬上限，封死「一直触发」） |
| ③ 自然消减 | 48h TTL + 两个主出口持续消耗（单条会过期，不是无限攒） |

**每次开口**：挑最想说的 1 条说，**只销说出口那条**，其余继续攒。

**其余配套（已定）**：

- 目标改成**卡级 owner_qq**（personas.owner_qq），不再写死全局 owner_qq；
- **删掉概率掷骰**（积压阈值已够，不再随机）；
- **上线前清一次存量**（线上 395 条 pending，其中 48h 内活着 122 条：baiwei 85 /
  huye 26 / jibril 11）——否则新机制一开直接连环触发。

## 3. 向量放哪算（工程切分，不是设计问题）

架构铁律已定好答案：

| 铁律 | 内容 |
|---|---|
| planner 不 import dsh.llm | planner 是纯调度，不碰大模型库 |
| core 不碰库 | 记忆表在 planner 的 SQLite，core 只算不存 |

所以「每次回复向量召回」拆两半：

```
第①半：算 query 向量（当前回复上下文的向量）
   → planner 发起 HTTP POST /v1/embed（端点已存在，阶段3回填就在用）
   → core 调 BGE-M3 算向量返回

第②半：拿向量去库里找相似（余弦检索）
   → planner 纯 Python 做（stdlib struct + 余弦距离，不碰 dsh.llm）
   → 读 memory_summaries.embedding 列（已回填），挑前几名
```

**骨架已铺好一半**：`/v1/embed` 端点 + `core_client.embed()` + `embedding` 列
都就位，只差「planner 写余弦检索 + 召回结果拼进上下文 + 提示词」。

成本：BGE-M3 几乎免费（我已核算，月 2500 万 token 用不完），**不是问题**。

## 4. 待拍板清单（✅ 已全部拍完，2026-11-03 清醒后）

1. ✅ 心事生产：**与摘要脱钩**，独立判断「想说没说」，不按 importance 切分；
2. ✅ 心事**保留独立挂账** `kind='pending'`，说出口那条才销（不是召回就销/全销）；
3. ✅ proactive **保留，降级为兜底出口**：积压 ≥5 触发 + 间隔 3~4h + 每天最多 3 次；
4. ✅ 提示词：只供材料 + 「接话用摘要 / 抛话题用心事」，要不要用模型自己判断；
5. ✅ importance **不恢复**：摘要回到 skip/摘要 粗判，心事独立判断，无需 0-10 打分。

## 4b. 已定稿补充（2026-11-03 凌晨，与图⑤对齐）

**心事出口意向（outlet）—— 已定方向**

- 心事生产时（summary/碎片时，有群聊原文上下文）顺带打 `outlet`：
  `private`（只想跟我说）/ `qzone`（憋不住发空间）/ `both`（都行）；
- **判断永远在有原文的地方做，出口只执行**：发空间那一刻不需要再判断重要性；
- **冲动日记删除**，并入心事体系当「空间出口」；空间发文不再是「挂人」，而是
  段子、「今天谁谁谁干了啥」、写给/表演给某个人看等；
- 私聊出口 = 向量召回 `outlet ∈ (private, both)`；空间出口 = qzone 驱动捡
  `outlet ∈ (qzone, both)`，公开审查后发（**importance 不参与**，摘要/心事都不打分）；
- 定时日记（scheduled）保留：只「回顾今天」，不产心事、不产冲动——日记写完就过去，
  不派生别的东西（堵死套娃）。

**表达学习（对话对）—— 已定根**

- 单元 = 真实 user→bot 对话对，不是 situation→style 抽象规则；
- 分两类：接话对（`[REPLY_TO:msg_id]`）+ 话题对（`[TOPIC]`）；
- **回复时自我标注，不事后猜**：flash/PRO 生成回复的同刻标「我接的是哪句」；
- 场景一（多人多话题）PRO 拿完整上下文当场精确标；场景二（单话题）flash 拿召回
  20 条整段当话题，标 `[TOPIC]`，提炼不出就拉倒（宁缺毋滥）；
- 每卡封顶 20 条 few-shot；先不搞「这句像她」标签；
- 先做接话对，话题对二期。

**行为学习 = 砍掉（不单独做本地模块）—— 已定（2026-11-03 修正）**

- 原结论「伪命题」表述不准确，修正为：行为学习**是存在的**（如群里大家调戏吉祥物、
  AI 学着跟着调戏），但**不值得单独做一个本地学习模块**：
- 群里的即时互动偏好，靠「当下上下文直接反应」即可，不需要记住；
- 跨会话的说话习惯（如话尾带喵、被调戏回表情包）归**表达学习**——表达学习新增
  第三种单元「互动习惯对」（我/群友做了什么 → bot 怎么回应），学法同对话对；
- 「防 bot 回机器 / 防复读」另挂守卫（清洗），不叫学习；
- 旧 `bridge.py _learn_auto_reply`（背自动回复原文）废弃不迁 v3。

**群虚拟用户语义边界 —— 已定**

- 群 = 地点，不进 user_profiles、不建好感、不建兴趣点；群级印象以后再说。

## 4c. 心事生命周期（完整定稿，2026-11-03 清醒后）

**一句话**：心事不是「重要的事」，是「想说但没来得及说的事」；说出口后不删，
降级成摘要，与起因互相指向，形成因果链。

### ① 产生（生产时分类出口意向）

- 做摘要的**同一次调用**里，独立问一句「这段有没有她想了但没来得及说的事」；
- 有 → 落一条 `kind='pending'`，并**当场打出口意向** `outlet`：
  `private`（只想跟我说）/ `qzone`（憋不住发空间）/ `both`（都行）；
- **出口意向在生产时就分类好**，说出口后的降级**不需要再判断出口**，只需记「说了没说」；
- 摘要本身不打 importance 分（回到 skip / 做摘要）。

### ② 说出口（三个出口）

| 出口 | 触发 | 标记 |
|---|---|---|
| 普通回复 | 每次回复时向量召回 + 提示词 | `said_via=reply` |
| 主动发起 proactive | 积压 ≥5 条（§2.4） | `said_via=proactive` |
| 空间发文 | qzone 驱动捡 `outlet ∈ (qzone,both)` | `said_via=qzone` |

### ③ 降级（不是删，是因果链）

说出口后 **pending 不删**，降级：

- pending 行标 `said_status='said'` + `said_via`（实际出口）+ `said_to_summary_id`；
- **另写一条 summary** 存「结果」：
  - 普通回复/主动发起 → 存「聊完后的对话结果」；
  - 空间发文 → 存「发出去的那段文案」；
- **因果链双向指向**：`pending.said_to_summary_id ←→ summary.said_from_pending_id`；
  - 这是**必要的设计，不是代价**：能回答「她当初为什么聊起这个」（起因）和
    「聊完之后怎么样」（结果）。

### ④ 召回过滤

- 向量召回**只召回 `said_status='unsaid'`** 的 pending；
- 已说的 pending 不删、不进话题候选，但永久留库可查（见 §4d 铁律）。

### ⑤ 因果链要能被大模型真用到（关键）

- 不是停留在设计：给 LLM 一个**可调用的查询工具**（如 `query_pending_causal`），
  让她能顺着 `pending` 找到结果 summary、顺着 summary 找到起因 pending；
- 工具语义：接话/回忆时，可查「这条心事的来龙去脉」。

### ⑥ 空间可扩展口子（模块化预留）

- `said_via` 只做**粗粒度出口**（reply / proactive / qzone）；
- qzone 底下再留 `qzone_action` **细粒度动作**：
  - 现在只有 `post`（发说说）；
  - 未来可加 `like`（点赞互动）/ `comment`（回复评论）等，**只加枚举值，不动表结构**；
- **入站通道预留**：未来 gateway 加一条「qzone 入站事件通道」
  （like / comment / reply_comment），**现在只标注、不建、不写代码**。

## 4d. 留档铁律（与溯源铁律并列）

- 记忆/心事/日记 **只软过滤，永不物理删除**；
- 48h / 3 天 TTL 只影响「是否进候选池」，记录永久留库可查；
- 理念（我的原话）：角色扮演是认真的事，跟角色有关的一切不随便消失，想翻就能翻。
  「忘记可以保护我们，但有时也会让我们后悔忘记了什么。」
