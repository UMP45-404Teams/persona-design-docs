## 1. 背景与动机

### 1.1 要解决的两件事

1. **跨群联动 + 主动开口**：bot 在各群潜水时，看到「有意思、值得跟我说」的事，
   能**主动**在私聊里开口（嚼舌根、吐槽、分享），而不是等我私聊它才说。
   要求是「**灵动**」，明确拒绝「定时推送打卡」。

2. **旧群聊长期记忆失效**：线上旧版群聊长期记忆几乎失效，根因是——

   | 旧版缺陷 | 后果 |
   |---|---|
   | 定时批量（每天 2 次） | 事件驱动性差，错过即时信息 |
   | 无游标 | 反复总结同一段 |
   | 只取最近 50 条「尾巴」 | 细颗粒度覆盖不到，中间内容被漏掉 |
   | LLM 自行判重要性后**直接丢弃低分** | 低分即记忆消失，出现记忆空缺 |

   结论：用**碎片记忆**取代旧定时批量总结，以细颗粒度持续覆盖，补齐记忆空缺。

### 1.2 核心思想（一句话）

**碎片是群聊记忆的新原料，但不是终点；长期记忆由「升级」产生。**

与旧版的本质区别不是「打不打分」，而是「**打分后干嘛**」：

- 旧版：低分 → 直接丢弃 → **记忆消失**；
- 新版：碎片先**全量落库**（3 天 TTL），打分只决定「是否升级成长记忆」——
  **打低了碎片也还在，只是不升级**。

## 3. 总体架构：两段式流水线

```
第 1 步  碎片生成（群聊视角，便宜模型）
        产出 ① 碎片摘要  ② 群聊重要性分
        落库 kind='fragment'（临时池，3 天 TTL，全量落、不设门槛）
              │
              ▼
第 2 步  冲动判断（私聊人设，独立调用）
        产出 分享冲动分 0–10
              │
   ┌──────────┴──────────┐
   ▼                     ▼
第 3a 群聊线              第 3b 私聊线
群聊重要性分 ≥ 7           分享冲动分 ≥ 8
→ 升级群聊长期记忆          → 拉原文 + 组织语言 + 私聊开口
  （chat_type='group'，      → 落私聊流记忆
   importance=7）             （chat_type='private'，
                              kind='diary'，importance=8）
```

**两条线各自人设、各自打分、各自存各自的流**——不串味、不越号。

### 3.1 为什么是「两段式」

- **第一段（便宜模型 + 碎片摘要）**：只判断「有没有冲动」，输出 0–10，**不组织语言**。
- **第二段（私聊人设 + 对应群原文）**：只有冲动 ≥ 8 才发生，按 `source_msg_range`
  回读该群原文，**基于事实**组织分享语，不靠摘要脑补。

这套两段式直接根除「摘要丢细节 → LLM 脑补 → 出戏」的失败模式。
原文回读默认 **100 条**（可配；数值非设计，跑通后调）。

## 4. 核心设计要点

### 4.1 触发 = 事件驱动，不是定时

每产出一批新碎片，就发起一次「冲动评估」。**评估权在私聊人设，不在代码计数器。**

### 4.2 双线打分分离（防维度偷换）

| | 群聊重要性分 | 私聊分享冲动分 |
|---|---|---|
| 产出时机 | 碎片生成时**顺带**产出 | 单独一次冲动判断调用 |
| 视角 | 群聊视角 | 私聊人设视角 |
| 用途 | 决定碎片是否升级为**群聊长期记忆** | 决定是否**私聊开口** |
| 阈值 | ≥ 7 升级群记忆 | ≥ 8 私聊开口 |

**为什么必须分离**：群聊重要性 ≠ 私聊分享欲。
**绝不能用私聊冲动替群聊记忆做存留决定**——否则「该被记住的事」会因为「不想说」而被丢弃，
反之亦然。分离让两条线互不污染，各自调各自的分。

### 4.3 三条记忆层的自然分层（不加第四层、不做快照）

| 层 | 存什么 | 会不会丢 |
|---|---|---|
| `fragment` 碎片 | 临时切片 | **3 天 TTL，会丢**（设计如此） |
| `diary` / `summary` 长期 | 事件本身 | **不丢**（无 TTL，衰减沉底但不删除） |
| 原文 `chat_messages` | 逐字记录 | 未来可能被清理 |

- 重要的约定/回忆落在第二层即**永久安全**，不依赖原文。
- 备忘：未来若引入原文清理，需**跳过已被 diary/summary 锚定的 `source_msg_range` 区间**；
  即使原文已失，记忆层仍保留事件本身，允许「记得事、记不清原话」，**禁止凭空编造原文**。

### 4.4 升级的 B 方案

冲动通过后**单独调 `/v1/summary`** 产完整事件摘要（**不与分享语同一次调用**，避免人设分心）；
`importance` 直接给定（群聊线 7、私聊线 8），**不再让 LLM 判**；
升级即推进该群总结游标（覆盖，避免常规循环重复总结同一段）。

## 5. 批次切取与调参

### 5.1 批次切取

**15 条实质消息**（去噪后计数）**或 20 分钟**，**先到先切**。

- 不追求「话题结束」这一无解状态机；
- 跨批次的碎片靠 `source_msg_range` + 时间相邻在召回时连起来；
- 可配置范围：条数 10–20、时长 10–40 分钟。

### 5.2 质量优先，零频率熔断

- **不用计数器限制冲动**（明确反对）。少是自然结果：冲动阈值高（默认 8），私聊人设自己筛。
- Prompt 明确「**宁可一整天不说，也不说一件不值得的**」。
- 仅保留**病理安全阀**：单号单日分享次数极高（如 ≥ 10）才触发，
  触发即视为 prompt 失控、需人工干预；我可随时用 `#休眠` 关停。

### 5.3 已定参数汇总

| 参数 | 值 | 备注 |
|---|---|---|
| 碎片 TTL | **3 天** | 临时池，过期自动失效 |
| 冲动阈值 | **8** | 私聊线开口门槛 |
| 群聊升级阈值 | **7** | 群聊线升级门槛 |
| 批次切取 | **15 条 / 20 分钟** | 可配 10–20 / 10–40 |
| 升级方案 | **B 方案** | 冲动后单独调 `/v1/summary` |
| importance | **给定 7 / 8** | 不再让 LLM 判 |
| 原文回读 | 默认 **100 条** | 可配，跑通后调 |

## 6. 隔离与安全边界

| 维度 | 决定 |
|---|---|
| **复用表** | `memory_summaries`，新增 `kind='fragment'`。复用现有字段：`expires_at`（TTL=3 天）、`resolved_at`（说过了就消解）、`bot_uin`（账号隔离）、`importance`（碎片存「群聊重要性分」，升级后存给定分） |
| **召回隔离** | `kind='fragment'` **绝不混入**现有召回 `MEM_KINDS_RECALL`（summary/diary/important/pending）。碎片只走专用入口：① 冲动评估 ②（可选）未来「群氛围感」 |
| **账号隔离** | `bot_uin` 严格隔离，**谁看到谁嚼**（角色C只嚼角色C所见，角色A只嚼角色A所见）；不给空串兜底 |
| **单向边界** | 碎片只允许 **群 → 私聊** 单向流动；禁止把「从 A 群听来的、在私聊说过的话」反向说回 B 群 |
| **数据流** | 注入的候选旁白**阅后即焚**（不落 `chat_messages`）；她真正发出的分享语**必须落库**（正常 outbound）；决策记录（号/群/批次/得分/推 or SKIP）**单独落**，供逐层调参 |
| **白名单** | 只从**白名单群**（bot 被允许参与/我关心的群）产碎片；不允许 bot 聊天的群根本不进池 |

### 6.1 日记（diary）的溯源与原文回链

- 私聊线升级出的日记**住在私聊流**（`chat_type='private'`、`target_id=我`、`bot_uin=对应号`），
  但**原料来自群聊**。
- 落库必须同时写四个溯源字段：`source_msg_range`（人读出处的文本）、
  `first_msg_at` / `last_msg_at`（机器回读原文的时间锚）、`target_id`（原群号）。
- 正文前缀标来源（如「〔来自群 533401080〕」）——**只写进记忆文本**，
  供她自己以后回忆时知道出处；她开口分享时**不带**机器腔前缀。
- 原文回链：用 `source_msg_range` 的时间锚 + `target_id` 走轨二 `_sync_read_raw_messages`
  回读原始聊天记录。

## 7. 连续性设计（「等你接话」挂起态）

主动 push 后**不能推完即走**：她推完一条，私聊会话进入**「等你接话」的挂起态**，
上下文保持连续，确保「嚼舌根」有来有回（你回「哈哈」，她能接着聊），
而不是一句话打卡后下一条就失忆。

挂起态的实现细节由实现阶段定，但**语义必须成立**。

## 8. 可观测性与逐层调参

每一层都落日志/计数：批次切了几次、冲动评估几次、私聊人设 SKIP 几次、开口几次、
群聊升级几次。

运行数天后按日志逐层调：

| 现象 | 调什么 |
|---|---|
| 切太碎 | 调条数 |
| 切太慢 | 调时长 |
| 太聒噪 | 调冲动阈值或 prompt |
| 太冷淡 | 调 prompt 的「分享胃口」表述 |
| 群聊升级过多/过少 | 调 7 分阈值 |

**可观测 + 可调，不接受拍脑袋定死。**

## 9. 与现有机制的关系

- 现有被动按需（我私聊**问起**才拉群记忆）**保留**，与本功能（主动：不问也开口）
  方向不同、不冲突。
- 碎片记忆补上「日常群聊记忆空缺」；升级后的 `diary`/`summary` 是长期记忆。
- 四种 kind 分立：`fragment` / `summary` / `diary` / `pending`，召回入口分立。
- 旧定时批量总结 `_once_summary`（每天 2 次 + 50 条一锅炖）**退役**，
  群聊记忆由「碎片 + 升级」完全接管；私聊/agent 流的日常总结机制暂沿用现有。

### 11.4 超时关窗 / 窗口退出

1. 窗口退出 = **LLM 自己判断「话题结束 / 失去兴趣」**，不是代码计时器
   —— 🟡 讨论级（AI_COLD_START L229），与「评估权在私聊人设」同构（D-R11 L390–391）。
2. **2026-11-02 定稿（我拍板，取代讨论级与早前「连续2次切片未达标」版本）**：
   - 打分语义 = 「是否愿意继续关注并跟用户吐槽」（0-10）。
   - **push 阈值 ≥8**（吐槽向我开口）；**关窗阈值 <7**；**7~8 中间态**：不 push 但继续关注。
   - 节奏自定：中间态与 push 后续都用 `[NEXT_INTERVAL:30~600秒]` 自定下次再看。
   - 用户意愿**不硬编码减分**：角色卡下次打分时自动结合语境判断用户自身意愿纳入打分。
   - 打分输入 = 45 条群切片 + 最近 10 条本地私聊上下文（判用户兴趣）。
3. 未定义：窗口关闭后是否/如何开启下一窗口（L225 仅说「第一次冲动触发后开启」，
